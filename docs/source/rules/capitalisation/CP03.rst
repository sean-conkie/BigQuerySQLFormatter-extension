========================================
Rule: Consistent Function Capitalisation
========================================

**Rule Code:** ``CP03``

**Name:** ``functions``

Overview
--------

Enforce casing only for built-in functions in the generated BigQuery function
catalog, including namespaced functions such as ``ai.generate`` and ``net.host``
and built-ins with a ``SAFE.`` prefix.
User-defined functions (persistent or temporary), user-defined table-valued
functions and calls not in the catalog are never changed: BigQuery user-defined
function names are case-sensitive. Quoted function names, strings and comments
are ignored. Argument identifiers are controlled separately by CP02.

Options
-------

``capitalisation_policy`` accepts ``lower`` (default), ``upper`` or ``consistent``.
Consistent uses the first matching built-in function in the file; a mixed-case
first function selects lowercase. User-defined and unknown functions do not
set the policy. The policy is recomputed after edits.

Set ``"CP03": { "options": { "capitalisation_policy": "upper" } }`` under
``bigquerySQLFormatter.rules`` in VS Code or ``rules`` in ``.bqsqlformatter.json``.
Invalid options report an error and reset this rule's options to defaults.

Examples
--------

Anti-pattern with the default policy:

.. code-block:: sql

    select SUM(a), Sqrt(b), dataset.MyFunc(c);

Quick fixes, Fix All and formatting produce:

.. code-block:: sql

    select sum(a), sqrt(b), dataset.MyFunc(c);

With ``upper``, built-in function names become uppercase, including their
unquoted namespace. With ``consistent``, ``select SUM(a), max(b);`` becomes
``select SUM(a), MAX(b);``. Fixes preserve line endings and support ``noqa``.
