=============================================
Rule: Consistent Boolean/Null Literal Casing
=============================================

**Rule Code:** ``CP04``

**Name:** ``literals``

Overview
--------

Enforce the configured capitalisation of ``null``, ``true``, and ``false``.
The default is lowercase. Mixed-case literals such as ``True`` and ``Null``
are checked too. Matching uses token scopes, ignoring strings, quoted
identifiers, comments, and identifier substrings such as ``true_value``.

Options
-------

``capitalisation_policy`` accepts:

* ``lower`` (default): require ``null``, ``true``, and ``false``.
* ``upper``: require ``NULL``, ``TRUE``, and ``FALSE``.
* ``consistent``: use the casing of the first matching literal in the file.
  If that first literal is mixed-case, use lowercase. Comments, strings, and
  quoted identifiers do not determine casing. The policy is recomputed on edits.

For example, in VS Code settings:

.. code-block:: json

    {
      "bigquerySQLFormatter.rules": {
        "CP04": { "options": { "capitalisation_policy": "upper" } }
      }
    }

In ``.bqsqlformatter.json`` use the same entry under ``rules`` instead.
Project option fields override editor option fields. No group-level option
defaults are supported. Unknown or invalid options report a visible error and
reset CP04's options to the default ``lower`` policy.

Examples
--------

With the default ``lower`` policy, this is an anti-pattern:

.. code-block:: sql

    select NULL missing_value, True is_active, FALSE is_deleted;

Quick fixes, Fix All, and formatting produce:

.. code-block:: sql

    select null missing_value, true is_active, false is_deleted;

With ``upper``, the same query becomes:

.. code-block:: sql

    select NULL missing_value, TRUE is_active, FALSE is_deleted;

With ``consistent``, ``select TRUE, null;`` becomes ``select TRUE, NULL;``,
while ``select true, NULL;`` becomes ``select true, null;``.
